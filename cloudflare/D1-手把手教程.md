# Cloudflare D1 手把手教程（写给用过 KV 的你）

你熟悉 KV，D1 就是「能写 SQL 的 KV」。KV 像一个大字典（`get`/`put` 一个整体），D1 像一个迷你数据库（能用 `SELECT`/`INSERT`/`UPDATE` 查改单条）。
本教程目标：让你**从零到留言板跑起来**，每一步都给复制即用的命令。

---

## 第 0 步：装好 wrangler 并登录（一次即可）
如果你以前用过 KV，这步大概率已经做过。没做的话：

```bash
npm install -g wrangler
wrangler login          # 浏览器弹出，授权你的 Cloudflare 账号
wrangler whoami         # 能显示你的账号邮箱 = 登录成功
```

---

## 第 1 步：建一个 D1 数据库（相当于 KV 里「新建一个命名空间」）

```bash
wrangler d1 create yanzien-guestbook
```

回车后会输出一段类似：

```
✅ Successfully created DB 'yanzien-guestbook' with D1 associated with production
├──────────────┬──────────────────────────────────────┐
│ d1_databases │                                      │
├──────────────┼──────────────────────────────────────┤
│ binding      │ DB                                   │
│ database_name│ yanzien-guestbook                    │
│ database_id  │ 1a2b3c4d-xxxx-xxxx-xxxx-xxxxxxxxxxxx │  ← 复制这一长串
└──────────────┴──────────────────────────────────────┘
```

**把 `database_id` 那串 UUID 复制下来**，等下填进 `wrangler.toml`。

> 💡 和 KV 的区别：KV 用 `id`（短哈希），D1 用 `database_id`（UUID）。功能上都是"给你的 Worker 绑一块存储"。

---

## 第 2 步：建表（KV 不需要这步，D1 需要）

KV 你直接 `put` 就行；D1 得先定义"表长什么样"。我们已经写好了建表语句 `schema.sql`，直接导入：

```bash
wrangler d1 execute yanzien-guestbook --file=./schema.sql
```

跑完会看到 `SELECT 0` / `executed` 之类提示，表示 `messages` 表建好了。表结构（你看一眼即可，不用记）：

| 字段 | 说明 |
|------|------|
| `id` | 自增主键 |
| `name` | 昵称 |
| `message` | 留言内容 |
| `status` | `pending` 待审核 / `approved` 已通过 / `hidden` 已隐藏 |
| `created_at` | 毫秒时间戳 |
| `ip` | 访客 IP（仅站长后台可见） |

---

## 第 3 步：填 wrangler.toml

打开 `wrangler.toml`，做两件事：

1. 确认 `main = "worker.js"`（用 D1 版，别被 KV 注释误导）。
2. 把第 1 步复制的 `database_id` 填进去：

```toml
[[d1_databases]]
binding = "DB"
database_name = "yanzien-guestbook"
database_id = "1a2b3c4d-xxxx-xxxx-xxxx-xxxxxxxxxxxx"   # ← 替换这里
```

> 你之前用 KV 的话，可能习惯在 toml 写 `[[kv_namespaces]]`。D1 用的是 `[[d1_databases]]`，名称不同而已。

---

## 第 4 步：设置两个「机密」（不写进文件）

KV 时代你大概没设过 secret（KV 权限跟着账号走）。本留言板有两个机密要用 `secret put`（**千万别写进 wrangler.toml**，会泄露）：

```bash
# 1) 后台审核令牌：自己随便定一串随机串，例如：
openssl rand -hex 16
# 假设输出 9f3c... ，下面填它
wrangler secret put ADMIN_TOKEN
# 提示输入时粘贴 9f3c... 这一串

# 2) Turnstile 私钥（你已决定开启验证码，必须配）
#    → 先在 Cloudflare 控制台创建 Turnstile 站点（见第 6 步）拿到 Secret Key
wrangler secret put TURNSTILE_SECRET
# 提示输入时粘贴 Turnstile 的 Secret Key
```

> `ADMIN_TOKEN` 是你后台「留言管理」里要输入的密码；`TURNSTILE_SECRET` 是服务端校验验证码用的私钥（和前台的 Site Key 是一对）。

---

## 第 5 步：部署

```bash
wrangler deploy
```

成功会输出类似：

```
Published yanzien-guestbook (x.x sec)
  https://yanzien-guestbook.<你的子域>.workers.dev   ← 复制这个地址
```

**这个地址就是 Worker 地址**，待会填进后台。

---

## 第 6 步：创建 Turnstile 验证码（你已决定开）

1. 打开 Cloudflare 控制台 → **Turnstile** → 「Add Site」。
2. 名称随意（如 `yanzien-site`）。
3. **域名**：填你的 GitHub Pages 域名 `yanzien.github.io`（本地调试可临时加 `localhost`）。
4. Widget Type 选 `Managed`（最稳）。
5. 创建后会得到两个值：
   - **Site Key**（明文，给人看的）→ 填进后台「留言方式 → Turnstile 站点密钥」
   - **Secret Key**（私密）→ 第 4 步已经 `wrangler secret put TURNSTILE_SECRET` 了

---

## 第 7 步：前台/后台接入

1. 打开 `https://yanzien.github.io/home/admin.html` → 「设置 / 云端 → 留言方式」
   - 模式：**Cloudflare Workers + D1**
   - Worker 地址：第 5 步复制的 `https://yanzien-guestbook.<子域>.workers.dev`
   - Turnstile 站点密钥：第 6 步的 Site Key
   - 保存（自动写回 `data/content.json` 并发布）
2. 打开「留言管理」标签 → 第一次会让你输入**管理员令牌**（即第 4 步的 `ADMIN_TOKEN`，只存你浏览器本地）
3. 去前台留言板试留一条 → 回到后台「留言管理」点「通过」→ 前台刷新即可看到。

---

## 常用运维命令（对照 KV 习惯）

| 想做的事 | KV 时代 | D1 时代 |
|---------|---------|---------|
| 看全部数据 | `wrangler kv:key list` | `wrangler d1 execute yanzien-guestbook --command="SELECT * FROM messages ORDER BY created_at DESC"` |
| 看某条 | `wrangler kv:key get xxx` | `wrangler d1 execute yanzien-guestbook --command="SELECT * FROM messages WHERE id=1"` |
| 清库（慎用） | `wrangler kv:key delete xxx` | `wrangler d1 execute yanzien-guestbook --command="DELETE FROM messages"` |
| 本地预览 | `wrangler dev` | `wrangler dev`（会自动连本地 D1 模拟） |

## 你可能想问

**Q：D1 和 KV 到底选哪个？**
A：个人留言板两者都行。D1 强一致（审核后立即可见）、查询灵活；KV 你更熟、零 SQL。**我们已经给了两个 Worker 文件**（`worker.js`=D1，`worker-kv.js`=KV），改 `wrangler.toml` 里的 `main` 和绑定即可切换，前台/后台代码完全不用动。

**Q：D1 要钱吗？**
A：免费套餐每天 500 万次读 / 10 万次写，个人站点基本零成本。

**Q：忘了 ADMIN_TOKEN 怎么办？**
A：再 `wrangler secret put ADMIN_TOKEN` 设一个新的即可。

**Q：Turnstile 一直验证失败？**
A：99% 是 Site Key 和 Secret Key 填反了，或 Turnstile 站点域名没包含 `yanzien.github.io`。
